Notes on CI/CD tools and practices.

<!--more-->

### Key Takeaways for CI/CD

1. **Continuous Integration (CI)** - developers frequently merge code changes into a shared repository, where each change is automatically built and tested.
2. **Continuous Delivery (CD)** - code changes are automatically prepared and validated so they are always in a releasable state, with the final release to production triggered manually.
3. **Continuous Deployment** - every change that passes automated testing is automatically released to production, with no manual step required.

### Idea behind CI/CD

CI/CD is a way of developing software in which you’re able to release code at any time in a sustainable way, reduce manual effort, and release faster.

### Deploying with a GitHub Actions Pipeline

A typical GitHub Actions CI/CD pipeline is defined as a workflow file (e.g. `.github/workflows/deploy.yml`) and runs through the following steps:

1. **Trigger** - the workflow is triggered by an event, such as a push or pull request to a specific branch (e.g. `main`).
2. **Checkout** - the pipeline checks out the repository's code using the `actions/checkout` action so the runner has access to it.
3. **Build** - the code is built or compiled, and dependencies are installed.
4. **Test** - automated tests are run against the build to catch issues before deployment.
5. **Package** - the application is packaged into a deployable artifact (e.g. a container image or build archive).
6. **Deploy** - the packaged artifact is deployed to the target environment (e.g. a server, container registry, or cloud service).
7. **Verify** - a post-deployment check (e.g. a smoke test or health check) confirms the deployment was successful.

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build
        run: npm install && npm run build
      - name: Test
        run: npm test
      - name: Deploy
        run: ./deploy.sh
```
